用别的 Agent？贴一份 JSON 就行

自定义 Agent 是数据不是代码：在「设置 → Agents → Add Agent → 自定义」粘贴一份定义，实测通过即接入。模板占位符覆盖会话目录与恢复参数，甚至支持 SQLite 型会话存储。插件 JSON 永不执行，只读打开、参数绑定，安全边界清晰。

查看支持细节 → 
// aider，一条插件就加上
{
  "name": "Aider",
  "executable": "aider",
  "resumeArgs": "--restore {id}",
  "sessionsDir": "{home}/.aider/sessions"
}

为什么原生

不是网页套壳，是一台 Mac 应用

Swift + SwiftUI

无 Electron、无 Chromium。无标题栏沉浸式三栏布局，左栏项目、中栏会话、右侧活动坞，与 macOS 的质感一致。

数据只在你机器上

配置 JSON 原子写盘；只索引 Agent 的原生会话文件，不复制内容、不上传任何数据，无需注册任何账号。

扫得快，刷得实时

64KB 头部探测加缓存，371MB 会话历史全量扫描从 9.1 秒降到 0.6 秒；FSEvents 监听目录，会话列表自动刷新。

安全边界明确

插件 JSON 永不执行；SQLite 只读打开、SQL 参数绑定防注入；插件声明的链接仅接受 HTTPS。

常见问题

你可能想问

CodeBay 会上传我的会话或代码吗？

不会。CodeBay 完全离线工作：它只读取各 Agent 存在本机的会话文件建立索引，不复制会话内容，没有账号体系，也没有任何遥测上传。

内置支持哪些 Agent？我想用的不在名单里怎么办？

内置 Claude Code、Codex、OpenCode、DeepSeek（dsh）、OMP、Pi 六个适配器。名单之外的 Agent 可以通过「自定义 Agent」接入：贴一份 JSON 定义（可执行文件、新会话/恢复参数、会话目录），实测通过即可使用，无需等待官方更新。

Agent 的 CLI 更新了，会话会不会找不到？

每个 Agent 的可执行文件路径、会话目录与参数都可在设置面板单独覆盖，优先级高于内置默认值，因此上游 CLI 升级路径或参数时你可以立刻修正。

多个 Agent 同时改一个仓库，会不会互相冲突？

CodeBay 用 Git 工作树做隔离：一个分支一份独立 checkout，各跑各的；多个仓库还可以组成「工作树组」一起切换。恢复会话时会话所在的工作树会一并就位。

对系统有什么要求？

macOS 14 或更新的 Apple Silicon / Intel Mac。CodeBay 本身不代理任何模型请求，你使用的 Agent CLI 需自行安装并配置好登录。
